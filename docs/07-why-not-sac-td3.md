# 7. 为什么选 PPO 而不是 SAC 或 TD3

本仓库附带了一份对比实验——`logs/algorithm_comparison.md`——其结论是 PPO 是这个任务的正确算法。这个结论碰巧是对的。但实验本身并不支持它。

本章做两件事：先解释同策略（on-policy）与异策略（off-policy）方法之间的真正区别，再诚实地重读那份实验。第二部分更有用，因为学会怀疑自己的基准测试，是比知道哪个算法赢了更具可迁移性的技能。

## 7.1 同策略与异策略

**同策略**方法（REINFORCE、A2C、TRPO、PPO）从当前策略生成的数据中学习。第 5 章说明了原因：代理目标只在 $\theta_\text{old}$ 附近才有效。数据被用上几个 epoch 后就丢弃。

**异策略**方法（DQN、DDPG、TD3、SAC）从一个经验回放缓冲区中学习，其中包含来自许多历史策略的数据。它们之所以能这样做，是因为它们学习的是 $Q(s,a)$，而贝尔曼最优方程（2.8）

$$
Q^*(s,a) = \mathbb{E}_{s'}\left[ r + \gamma \max_{a'} Q^*(s',a') \right]
$$

完全不涉及生成该转移的策略。任何 $(s,a,r,s')$ 元组都是 $Q^*$ 的有效训练样本，不管它是谁产生的。

由此带来的后果：

| | 同策略（PPO） | 异策略（SAC、TD3） |
|---|---|---|
| 样本复用 | 用几个 epoch，然后丢弃 | 无限期复用，来自经验回放缓冲区 |
| 样本效率 | 低 | 高 |
| 配合快速仿真器时的墙钟效率 | **高** | 往往更低 |
| 并行性 | 随环境数几乎线性扩展 | 受梯度步吞吐量限制 |
| 稳定性 | 好；信赖域是显式的 | 脆弱；基于学到的 $\max_a Q$ 做自举 |
| 对奖励尺度的敏感度 | 低（优势经过标准化） | 高（$Q$ 的量级直接参与计算） |

## 7.2 真正起决定作用的论据

通常的说法是“异策略的样本效率更高”，这没错。但对这个问题来说，它是一个错误的衡量维度。

样本效率只在样本昂贵时才重要——真实机器人、缓慢的仿真器、需要人参与的回路。而在这里，一个样本的代价是十个 MuJoCo 物理步。在开发本仓库的那台机器上，单个环境每秒大约产生 810 个控制步，十六个环境并行时，包括梯度更新在内的端到端吞吐量约为 620 样本/s。在 GPU 上使用 MJX（第 17 章），这个数字会达到数十万。

当样本几乎免费时，真正的约束变成了**单位墙钟时间内的梯度步数**，局面随之反转：

- PPO 对全部 16 个环境做一次批量前向传播，然后在 8192 条转移上做 20 次梯度步。增加环境在学习这一侧几乎没有额外代价。
- SAC 默认每个环境步做一次梯度步，而每次梯度步都涉及两个 Q 网络、两个目标网络、一个策略，以及一次熵温度更新。扩展到 4096 个并行环境，意味着要么每个环境步做 4096 次梯度步（荒谬），要么回放比低到样本效率优势荡然无存。

还有第二个论据，人们较少提及，但对这个任务至少同样重要。异策略方法通过学到的 $\max_{a'} Q(s', a')$ 做自举。在一个富含接触的系统中，$Q$ 具有尖锐的结构——足端要么落地，要么没落地——而函数逼近器会高估含噪函数的最大值。TD3 的两大招牌特性（裁剪双 Q、延迟策略更新）完全是为了对抗这种高估而存在的，而它们也只取得了部分成功。PPO 从不对动作取最大值，所以这种失效模式根本不存在。

## 7.3 异策略真正占优的场景

为了对被否定的方法公平起见：

- **真实机器人上的学习。** 当每个样本都要耗费数秒墙钟时间和硬件损耗时，经验回放是决定性的。
- **长视界的稀疏奖励。** 经验回放能让罕见的成功被反复重温；PPO 看到一次罕见的成功后就把它扔掉了。
- **小规模问题。** 在只有一个环境、仿真器又慢的情况下，同样的墙钟预算内 SAC 通常会胜过 PPO。

还要诚实地补充一句：尤其是 SAC，只要调得好，在运动控制基准上是一个非常强的算法。文献中在大规模并行足式运动控制（Isaac Gym、legged_gym、MJX）里偏好 PPO，是一种关于*并行场景*的偏好，而不是声称 PPO 是更好的算法。

## 7.4 重读本仓库的对比实验

仓库附带的实验：

> 每个算法 1,000,000 个时间步，单环境（`DummyVecEnv`），相同的环境、奖励和 PD 控制器，`cmd_vel = [0.5, 0, 0]`，不使用课程学习。

| 指标 | PPO | SAC | TD3 |
|---|---|---|---|
| 平均奖励 | 182.78 | 232.45 | **259.39** |
| 平均回合长度 | 264.2 | 243.7 | **440.2** |
| 存活率 | 0.0% | 0.0% | **10.0%** |
| 平均前进速度 | **0.140** | 0.027 | 0.012 |

以及结论：*“PPO 是这个任务的最佳算法。”*

这里有四个问题，按严重程度从轻到重排列。

### 7.4.1 TD3 在运行时没有探索噪声

`scripts/compare_algorithms.py` 构造 TD3 时没有传入 `action_noise` 参数。Stable-Baselines3 的默认值是 `action_noise=None`，而 TD3 的策略是**确定性**的。SAC 通过其熵正则化的随机策略进行探索，TD3 则不同，它没有其他任何探索来源。

所以 TD3 实际上是在一个 12 维连续控制问题上，在几乎没有任何探索的情况下运行的。它的结果不是对 TD3 的测量；它测量的是一个从不尝试任何新东西的确定性策略会做什么。它收敛到原地站立是意料之中的结果，并不能告诉我们关于这个算法的任何信息。

标准的修复方法是 `action_noise=NormalActionNoise(mean=zeros(12), sigma=0.1*ones(12))`。

### 7.4.2 相同的时间步数不等于相同的计算量，也谈不上对谁公平

三个算法各自获得了 1M 个环境步。但是：

- PPO 使用 `n_steps=2048`、`n_epochs=10`、`batch_size=64`，每个 rollout 做 $10 \times 2048/64 = 320$ 次梯度步，整个运行下来约 156,000 次梯度步。
- SAC 和 TD3 使用 `train_freq=1, gradient_steps=1`，每个环境步做一次梯度步：共 1,000,000 次梯度步，每次都要计算两个 critic 和一个目标网络。

在同样的“预算”下，异策略的运行用掉了数倍的计算量。按相同时间步数做比较是惯例，但应当同时报告墙钟时间，而这里没有。

### 7.4.3 单环境是 PPO 最不利的情形

这次对比使用的是只有一个环境的 `DummyVecEnv`，然后得出 PPO 最好的结论——同时又在分析中指出 PPO“从并行环境中获益最多（主训练运行中为 8 倍）”。因此，这个实验测量的是对胜出者最不利的配置，而支撑结论的理由却来自另一次设置不同的*其他*运行。不管这个实验说明了什么，它说明的都不是结论所声称的东西。

### 7.4.4 环境对三个算法来说都是坏的

正是这一点让结果彻底作废。

三个算法都是在 v1 环境上训练的，在该环境中 `default_joint_pos` 是 `qpos0`——十二个关节全部为零——而不是 Go2 的站立姿态（第 14 章，bug B1）。在 `action_scale = 0.5` 下，任何策略都无法指令机器人站立所需的 $-1.8$ rad 小腿角度，更不用说行走了。

这个实验并不是在一个运动任务上比较三种算法。它是在一个运动在**运动学上根本无法达到**的任务上比较三种算法，测量的是哪一种退化得最体面。平均前进速度——0.14、0.027、0.012 m/s——基本上都是零。给它们排名，就是在给噪声排名。

### 这些数字唯一真正说明的东西

再看一眼奖励那一列。TD3 得到了**最高**的平均奖励（259），却实现了**最低**的前进速度（0.012 m/s）。SAC 的得分比 PPO 高，移动速度却慢了五倍。

这不是一个算法层面的结果。它是一个**奖励函数层面的结果**：在 v1 的奖励下，原地站着比尝试行走得分更高。存活奖励是 0.5/步，速度跟踪项上限为 2.0/步，但它乘了一个指数因子，静止不动的机器人仍能拿到其中的 $\exp(-0.25/0.25) = 0.37$，也就是白拿 0.74/步。与此同时，每一个惩罚项都在惩罚真正行走所需的动作。

所以这张对比表确实是真实的证据——但它是第 10 章关于奖励设计的论点的证据，而不是第 7 章关于算法的论点的证据。这一点值得细细体会：这个实验包含了一个真实而重要的发现，却被归到了错误的结论之下。

## 7.5 如何正确地进行这项对比

如果你想重做这个实验：

1. **先修好环境。** 在 v2 上运行，在那里站立和行走都是可达的。
2. **给 TD3 加上探索噪声。** `NormalActionNoise(sigma=0.1)`。
3. **匹配计算量，而不只是样本数。** 在报告时间步数的同时报告墙钟时间，并把 SAC/TD3 的 `gradient_steps` 设成一个站得住脚的值。
4. **让每种配置在其设计所针对的环境数量下运行。** PPO 用 16 个以上的环境，SAC/TD3 用 1–4 个。在同一个共享的环境数量下比较它们，必然会让其中一方吃亏。
5. **多个随机种子。** 至少三个。单随机种子的强化学习结果几乎毫无意义；在这个任务上，不同随机种子之间的方差很容易超过上面报告的不同算法之间的差异。
6. **测量你真正关心的东西。** 在 v2 下，正确的指标是整个指令范围内的跟踪误差（`scripts/evaluate.py --grid`），而不是某一个固定指令下的前进速度。

`scripts/compare_algorithms.py` 仍然存在，也仍然能运行。请把它的输出当作那个实验的起点，而不是一个已完成的结果。

## 7.6 小结

PPO 在这里是正确的选择，但理由关乎所处的*场景*，而不是算法上的优越性：样本便宜，并行是扩展的方向，奖励是稠密的，而接触动力学让学到的 $\max_a Q$ 成为一种负担。

仓库附带的对比实验得出了这个结论，却没有支撑它。把这一发现保留在文档里，而不是悄悄删掉那个文件，这本身就是用意所在——做出一个不支持自身结论的实验是很正常的事，而事后能察觉到这一点，才是值得拥有的技能。
